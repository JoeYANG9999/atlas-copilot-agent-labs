贯穿全程的复盘三问

每个环节结束，学员都要能回答

讲师按这三问收口；学员手上有一张复盘卡，每格写一句话

问 1

我用了 Copilot 的什么功能？

说出功能名字：Agent 模式、Prompt 文件、MCP、Skill、gh-aw……不是「我点了一下」。

问 2

它替我做了什么？

说出机制：它读了哪些文件、调了哪个工具、改了哪几行、在哪里运行。

问 3

这对我们的项目意味着什么？

说出价值：省了谁的时间、谁能自己维护、能不能复用到别的场景。

关于 GitHub Copilot app

学员电脑由公司管控，多半装不了桌面应用，实验统一在 Codespaces 里做；Codespaces 里的 Copilot Chat Agent 模式和 app 是同一套核心能力。讲师在开场用 app 演示 3 分钟同一件事，告诉学员「回去在自己电脑上也可以这样用」。

Lab-01 · 行业洞察智能体 · MCP + gh-aw · 45 分钟

从「我能用」到「每周一自动给全组用」

同一套 MCP 工具，先在 VS Code 里交互式用，再用 gh-aw 放到云端定时跑

步骤学员做什么用到的功能验收
1 用起来 · 10'Agent 模式运行 /industry-insight，看智能体依次调 4 个 MCP 工具出周报Prompt 文件 · MCP周报页头显示「模式：智能体研判」
2 改成自己的 · 10'在 focus.md 加一个自己关注的行业（只改「搜索」「关注什么」两行），再跑一次—（只改 Markdown）周报里出现新行业，带来源链接
3 vibe coding · 15'让 Copilot 加 MCP 工具「客户雷达」search_signals(keyword)：按客户名 / 竞品名搜本周信号；重启 MCP 后问「宁德时代本周有什么动静」Agent 模式 · /tests · MCP智能体调用了新工具，返回带链接的信号
4 上云 · 10'把改动推到自己的分支 student/<名字>，读懂 industry-insight.md 四块配置，gh aw compile，在自己分支上触发工作流gh-aw · GitHub ActionsActions 里看到自己的运行；休息回来看到自己行业的周报（Issue / PR）
第 4 步：gh-aw 讲清楚这四块
  • 触发：schedule 每周一 8 点 + workflow_dispatch 手动触发
  • 网络白名单：智能体在防火墙里运行，只能访问列出的域名。加新的 RSS 源要同时加白名单再 compile（Google News 搜索不用）
  • safe-outputs：智能体本身只读，结果只能通过建 PR / Issue 提交，人审核后才进主干
  • 编译：.md 是给人读写的源，gh aw compile 生成 Actions 真正运行的 .lock.yml
复盘卡 · Lab-01
用了什么
Prompt 文件 · MCP 服务器 · Agent 模式写代码 · gh-aw
它做了什么
MCP 工具抓取、去重、回填链接；模型只负责挑重点、判断影响；gh-aw 把同一套工具放到云端按时运行
对项目意味着
不用每周人工追几十个网站；业务同事改 focus.md 就能换行业；数据源封装一次，VS Code、gh-aw、Studio 都能复用；结果必须经人审核才进主干
Lab-02 · 知识总结智能体 · Skills + Copilot SDK · 45 分钟

把团队的汇报规范，变成谁都能调用的服务

同一份 SKILL.md：在 Chat 里用一次，再通过 Copilot SDK 做成网页和 API

步骤学员做什么用到的功能验收
1 用起来 · 10'Chat 里让 Copilot 把一篇文章做成 6 页汇报 PPT，下载用 PowerPoint 打开Agent Skills（自动选中）每页标题是结论句、文字可编辑
2 改成自己的 · 10'改 SKILL.md 的「团队汇报规范」一条，再生成一次对比—（只改 Markdown）新 PPT 体现了改动
3 vibe coding · 15'让 Copilot 在网页上加一种「公司品牌风」（学员描述自己公司的配色）Agent 模式 · Edit 模式选新风格生成的 PPT 用了指定配色
4 跑服务 · 10'npm run dev，网页上选「本周行业洞察周报」生成 PPT；读一眼 lib/copilot.ts 看 SDK 怎么加载 SkillCopilot SDK进度页能下载 PPT
讲师要点
  • 第 1 步和第 4 步用的是同一份 SKILL.md：Chat 里是人在用，SDK 里是程序在用
  • 生成一次 PPT 约 3~5 分钟，等的时候带读 lib/copilot.ts 的 skillDirectories
  • 第 3 步只动 lib/styles.ts 一个文件（+ 一段 CSS），混合学员也能做完

用了什么
Agent Skills · Copilot SDK · Agent 模式写代码

前置条件与代价

评审前要知道的

gh-aw「每人自己跑一次」需要

  • 学员对本仓库有写权限（能推自己的分支），同时用规则保护 main，防止误推
  • 工作流读仓库 Secret COPILOT_GITHUB_TOKEN：全班共用讲师的令牌，额度记在讲师名下；或评估 gh-aw 的「用 Actions 令牌调用 Copilot」（需企业集中计费，未验证）
  • 企业目前禁止 Actions 建 PR，结果以 Issue + 分支形式出现；30 人会产生约 30 个 Issue，课后统一关闭
  • 每次运行约 5 分钟，放在休息前触发，休息回来看结果

其他代价

  • Lab-03 连接器冲突（讲师建好 × 每人连自己的）：首选「建连接时填 host」，未验证；保底学员自己导入 openapi.yaml
  • 热身和 3 道代码题都要做参考答案分支，并逐题确认 Copilot 照提示词能做出来
  • 全班同时写代码、生成 PPT、跑 gh-aw，Copilot 额度消耗明显上升，课前确认企业预算
  • 进阶题全部挪到课后：Lab-01 加数据源 + 白名单、Lab-02「汇报对象」选项

  • 功能地图的 12 个功能，有没有要加的（如 Copilot CLI、Copilot cloud agent）或要删的
  • 复盘卡「对项目意味着」这一栏的说法，是否贴合阿特拉斯业务同事的语言
  • gh-aw 用全班共用讲师令牌，还是先验证 Actions 令牌方案
  • Lab-01 第 4 步只给 10 分钟，是否够推分支 + 编译 + 触发
  • 复盘卡做成纸质、在线表单，还是写在仓库里的 Markdown
  • 评审通过后的顺序：答案分支 + 仓库权限 → 各 README 改写 → 讲师彩排
